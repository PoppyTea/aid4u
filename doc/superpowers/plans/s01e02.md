## Pipeline (workflow.md, przeniesiony na findhim)

### 1. Research — `findhim_001`
- Odtwórz i zapisz listę podejrzanych (name, surname, birthYear) →
  `tasks/s01e02_findhim/data/suspects.json`
- Pobierz `findhim_locations.json`, sprawdź strukturę (kod `PWR0000PL`, lat/lon)
- Dry-run `POST /api/location` dla jednej osoby — sprawdź kształt odpowiedzi
- Dry-run `POST /api/accesslevel` dla tej samej osoby — sprawdź kształt odpowiedzi
- DONE gdy: wiadomo co przychodzi z każdego endpointu

### 2. TDD — `findhim_002/003`
- Test `haversine_distance` (znane punkty, oczekiwana odległość)
- Test `find_nearest_plant` (dopasowanie osoby do najbliższej elektrowni)
- Test parsowania `birthYear` z pełnej daty (np. `1987-08-07` → `1987`)
- `uv run pytest` — testy muszą failować (czerwone) przed implementacją

### 3. Implementacja — `findhim_004`
- `haversine_distance` + `find_nearest_plant` (czyste funkcje)
- Klienci API: `get_locations(name, surname)`, `get_access_level(name, surname, birthYear)`
- Pipeline: podejrzani → lokalizacje → odległość do elektrowni → accessLevel dla trafienia
- `setup_observability()` jako pierwsza linia + instrumentacja Langfuse
- Zabezpieczenie pętli agenta (jeśli function calling): max 10–15 iteracji
- `uv run pytest` → zielone

### 4. Weryfikacja — `findhim_005/006`
- `uv run run.py solve s01e02 --dry-run`
- Sanity-check ręczny: odległość + accessLevel wiarygodne
- Skill `verification-before-completion` musi potwierdzić przed "done"

### 5. Submission — `findhim_007`
- `uv run run.py solve s01e02` → wysyłka do hub.ag3nts.org
- Potwierdź `{FLG:...}` w output / `uv run run.py status`
- Wpisz flagę na hub.ag3nts.org (przeglądarka), dopiero wtedy `task done` na GOAL
