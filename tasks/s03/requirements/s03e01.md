## Przed podejściem (oryginał, sprzed implementacji)

**Zadanie:** 10 000 plików JSON z odczytami sensorów. Zgłoś ID plików zawierających
anomalie: dane poza normą, sprzeczność notatka-operatora↔dane, albo czujnik zwracający
pole którego nie powinien. Nagroda za koszt: to zadanie *jest* o optymalizacji, nie o
znalezieniu każdej anomalii za wszelką cenę.

## Pułapki (potwierdzone przez społeczność — `source/community-intel.md`)

- Reguły anomalii #2 i #3 są NIEZALEŻNE od #1: plik z idealnymi odczytami, ale
  notatką o awarii, TAKŻE jest anomalią. To najczęstsza pomyłka koncepcyjna w
  komentarzach.
- Konsensus punktów kontrolnych: ~46 plików wypada z checków deterministycznych,
  tylko ~6 więcej dochodzi z klasyfikacji notatek. Jeśli LLM zwraca setki — prompt
  za luźny.
- ~9953 notatek → ~2000 unikalnych → ~261 unikalnych fraz po rozbiciu na przecinkach.
  Batche po 50-200, model zwraca SAME INDEKSY, nie treść.
- ID plików zaczynają się od 1, nie 0.
