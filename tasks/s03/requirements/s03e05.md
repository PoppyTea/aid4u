## Tryb porażki #1: agenci prawie nigdy nie odkrywają `/api/books`

Tam siedzi legenda mapy (symbole) i reguły ruchu. Agenci zapętlają się pytając
`/api/maps` o legendę której tam nie ma, potem HALUCYNUJĄ nieistniejące symbole.
**Prewencja:** wpisz wprost w system prompt "poszukaj też books/instrukcji", nie
polegaj na tym że agent sam wpadnie na pomysł.

## Algorytm planera — ustalony 2026-08-20

**BFS/Dijkstra po stanie `(x, y, pojazd)` z frontem Pareto po zasobach.** Koszty są
UŁAMKOWE (rakieta 1.0 paliwa/0.1 jedzenia, auto 0.7/1.0, koń 0/1.6, marsz 0/2.5), a
budżety DWA i niezależne — więc:
- zwykły BFS po siatce liczy najmniej ruchów, a nie wykonalność (udokumentowany tryb
  porażki: „plan zachłanny zawodzi"),
- Dijkstra po jednym koszcie wymaga zlania paliwa i jedzenia w skalar, co gubi
  poprawność — trasa tania w paliwie bywa droga w jedzeniu,
- DP po zdyskretyzowanych zasobach wymaga przeskalowania ×10 do liczb całkowitych i
  puchnie do ~4M stanów bez potrzeby,
- **Pareto**: przy dwóch budżetach istnieje tylko porządek CZĘŚCIOWY. Dla każdego
  `(x, y, pojazd)` trzymamy zbiór nieZdominowanych par `(zużyte_paliwo, zużyte_jedzenie)`;
  para odpada tylko gdy inna jest nie gorsza na OBU wymiarach. Dokładne, bez błędu
  dyskretyzacji, a przy 10×10 i ~4 pojazdach — trywialnie małe.

`dismount` modelujemy jako **krawędź w grafie stanów** (zmienia składową „pojazd", a więc
tabelę kosztów i przejezdności), nie jako dodatek — patrz tryb porażki #2 niżej.

## Tryb porażki #2: nieodkryta mechanika `dismount`

Trzeba móc zejść z pojazdu i dokończyć trasę pieszo — modele tego nie odkrywają same.
Zweryfikowany działający fragment promptu: *"It is possible that other actions that
we don't know about can be used. For example, we know that it is possible to get off
current vehicle."*

## Inne gotchas

- `/api/wehicles` (literówka, jak zwraca ją sam toolsearch) i poprawna pisownia obie
  bywają 404 dla części uczestników — nie ufaj ślepo temu co zwróci toolsearch.
- Do zapytania o mapę wystarczy sama nazwa miasta — nie przesadzaj ze złożonością
  zapytania.
- Budżet jest CIASNY — plan zachłanny (najkrótsza trasa) zawodzi, trzeba faktycznie
  symulować zużycie zasobów krok po kroku.
